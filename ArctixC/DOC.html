ArctixC — SDK Documentation

One standalone ArctixC.dll + ArctixC.lib — memory, buffers, virtual memory, threads

v0.3.0

The single-DLL systems SDK

ArctixC ships as one independent binary — ArctixC.dll with ArctixC.lib and the include/arctixc/ headers. There are no ArctixC.Memory.dll or ArctixC.Thread.dll files: every subsystem below lives in the same DLL, so an app ships exactly one binary. C++ consumers use the arctix:: namespace; C consumers use the flat Arctix_* / ArctixC_* ABI from arctixc/c_api/*.h (genuinely C-compilable headers).

Foundation

Version macros + ArctixCStatus codes shared by every subsystem. Zero dependencies.

Memory

Aligned Allocator with statistics, O(1) MemoryPool, owning Buffer, header-only SecureZero / MemEqual / Fnv1aHash64.

Virtual memory

Direct OS page control: VirtualReserve → VirtualCommit → VirtualDecommit → VirtualRelease, plus VirtualProtectMemory.

Threads

Move-only Thread with caught worker exceptions, a FIFO ThreadPool, and ParallelFor index loops.

✦Use it — C++

  1. Link ArctixC.lib, add include/ to the include path, ship ArctixC.dll next to the exe.
  2. Include only what you use, e.g. #include <arctixc/memory/buffer.hpp> (or the arctixc.hpp umbrella).
  3. Build bytes in a Buffer, allocate with Allocator/MemoryPool, run work in a ThreadPool.

✦Use it — pure C

  1. Include <arctixc/c_api/memory.h> and/or <arctixc/c_api/thread.h> from any .c file.
  2. Create handles (Arctix_CreateAllocator, Arctix_BufferCreate, ArctixC_PoolCreate …).
  3. Destroy every handle you create; NULL is always safe to pass.

✦Build & ship

From the Arctix/ root: powershell -ExecutionPolicy Bypass -File ArctixC\build.ps1 (configures CMake + Ninja, Release). Outputs land in ArctixC/build/Release/: ArctixC.dll, ArctixC.lib, test and example exes. ctest -C Release runs MemoryTests, ThreadTests, ExtendedTests and the pure-C CApiCheckBuild. The script fails if a split ArctixC.Memory.dll / ArctixC.Thread.dll is ever produced again.
